# Client API — two-phase compilation

As of `80c7371`, the compiler exposes two functions: `extract()` and `compile()`.

## Why two phases

A Brevity file can declare dependencies on remote actors via its top-level `< ... >` constructor header. Before compiling, the host needs to resolve those dependencies — fetching interfaces from the actor tree. `extract()` gives the host everything it needs to do that resolution without compiling the file. Once resolved, `compile()` takes the AST and any resolved interfaces and produces target code.

This eliminates double-parsing: the old single-pass `compile(source)` had to parse the source just to discover dependencies, then parse again after resolution.

## `extract(source) -> { ast, interface, dependencies }`

Parse source into AST. No validation, no codegen. Fast, side-effect free.

```js
import { extract } from 'brevity-lang';

const { ast, interface: iface, dependencies } = extract(`
  <
    "/services/remote": (Remote) { call: (Text) -> (Text) }
  >
  @go = { result Text = Remote.call("hello"); -> :result }
`);
```

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `ast` | object | Parsed AST — opaque, passed to `compile()` |
| `interface.service` | string | Service document for this actor's public interface |
| `dependencies` | string[] | Paths declared in the file's `< ... >` header (e.g. `["/services/remote"]`) |

**`interface.service`** is the actor's public API as a service document string. The host can publish this so other actors can validate calls at compile time. Example output:

```
{
  go: () -> (result: Text)
}
```

**`dependencies`** lists the dependency paths the host needs to resolve before calling `compile()`. If empty, the file has no remote dependencies and can be compiled immediately.

## `compile(ast, options?) -> string`

Validate and generate target code.

```js
import { extract, compile } from 'brevity-lang';

const { ast } = extract(source);
const output = compile(ast, {
  target: 'js',       // 'js' | 'rust' | 'erlang'  (default: 'js')
  remotes: [           // resolved interfaces for declared dependencies
    { path: '/services/remote', service: '{ call: (Text) -> (Text) }' },
  ],
});
```

**Options:**

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `target` | `'js' \| 'rust' \| 'erlang'` | `'js'` | Compilation target. Also reads `BREVITY_TARGET` env var. |
| `remotes` | `{ path, service }[]` | `null` | Interfaces for declared dependencies, keyed by path. |

**Returns** the compiled source code as a string — an ES module (JS), a Rust `main.rs`, or an Erlang module.

**Throws** on validation errors: type mismatches, undefined references, invalid remote calls against the provided interfaces, etc.

## Typical host flow

```js
import { extract, compile } from 'brevity-lang';

// 1. Parse
const { ast, dependencies } = extract(source);

// 2. Resolve dependencies (host-specific — tree lookup, HTTP, cache, etc.)
const remotes = [];
for (const path of dependencies) {
  remotes.push({ path, service: await fetchInterface(path) });
}

// 3. Compile
const js = compile(ast, { target: 'js', remotes });
```

For files with no declared dependencies, step 2 is skipped:

```js
const { ast } = extract(source);
const js = compile(ast);
```

## Quick one-liner (no dependency resolution)

```js
import { extract, compile } from 'brevity-lang';
const output = compile(extract(source).ast, { target: 'erlang' });
```
