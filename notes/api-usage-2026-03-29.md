# Client API — two-phase compilation

As of `80c7371`, the compiler exposes two functions: `extract()` and `compile()`.

## Why two phases

A Brevity file can declare dependencies on remote actors via `uses`. Before compiling, the host needs to resolve those dependencies — fetching service manifests from the actor tree. `extract()` gives the host everything it needs to do that resolution without compiling the file. Once resolved, `compile()` takes the AST and any resolved manifests and produces target code.

This eliminates double-parsing: the old single-pass `compile(source)` had to parse the source just to discover `uses` declarations, then parse again after resolution.

## `extract(source) -> { ast, manifest, useDecls }`

Parse source into AST. No validation, no codegen. Fast, side-effect free.

```js
import { extract } from 'brevity-lang';

const { ast, manifest, useDecls } = extract(`
  uses Remote { call: (Text) -> (Text) }
  @go = { result Text = Remote.call("hello"); -> :result }
`);
```

**Returns:**

| Field | Type | Description |
|-------|------|-------------|
| `ast` | object | Parsed AST — opaque, passed to `compile()` |
| `manifest.service` | string | Service document for this actor's public interface |
| `useDecls` | string[] | Names of remote actors this file depends on (e.g. `["Remote"]`) |

**`manifest.service`** is the actor's public API as a service document string. The host can publish this so other actors can validate calls at compile time. Example output:

```
{
  go: () -> (result: Text)
}
```

**`useDecls`** lists the `uses` dependencies the host needs to resolve before calling `compile()`. If empty, the file has no remote dependencies and can be compiled immediately.

## `compile(ast, options?) -> string`

Validate and generate target code.

```js
import { extract, compile } from 'brevity-lang';

const { ast } = extract(source);
const output = compile(ast, {
  target: 'js',       // 'js' | 'rust' | 'erlang'  (default: 'js')
  remotes: {           // resolved service manifests for uses declarations
    Remote: '{ call: (Text) -> (Text) }',
  },
});
```

**Options:**

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `target` | `'js' \| 'rust' \| 'erlang'` | `'js'` | Compilation target. Also reads `BREVITY_TARGET` env var. |
| `remotes` | `Record<string, string>` | `null` | Service manifests for `uses` declarations, keyed by actor name. |

**Returns** the compiled source code as a string — an ES module (JS), a Rust `main.rs`, or an Erlang module.

**Throws** on validation errors: type mismatches, undefined references, invalid `uses` calls against the provided manifests, etc.

## Typical host flow

```js
import { extract, compile } from 'brevity-lang';

// 1. Parse
const { ast, useDecls } = extract(source);

// 2. Resolve dependencies (host-specific — tree lookup, HTTP, cache, etc.)
const remotes = {};
for (const name of useDecls) {
  remotes[name] = await fetchServiceManifest(name);
}

// 3. Compile
const js = compile(ast, { target: 'js', remotes });
```

For files with no `uses` declarations, step 2 is skipped:

```js
const { ast } = extract(source);
const js = compile(ast);
```

## Quick one-liner (no dependency resolution)

```js
import { extract, compile } from 'brevity-lang';
const output = compile(extract(source).ast, { target: 'erlang' });
```
