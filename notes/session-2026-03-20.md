### `@` prefix on wire format for public functions
- Public function names now include `@` on the wire: `op: "@test"` instead of `op: "test"`
- `public: true` flag removed from AST — the `@` prefix IS the marker
- Public and private functions with the same base name can coexist (`@double` vs `double`)
- Parser, validator, all three codegens, and 47 test files updated
- Wire format for set handler: `@<-`

### `use` → `uses` keyword
- Lexer keyword and parser updated
- Test files already used `uses`; updated 3 test source strings in type_dependency, interop, external_send

### `as Type` → `self as Type`
- `self` prefix now required on as-clauses in actor bodies
- `=` delimiter required after type: `self as Integer = -> 1`
- Supports delimited (`self as Integer = -> 1`) and lineal (multi-line with `=`) forms
- Error messages say `'self-as'` instead of `'as'`
- Parser detection changed from bare `as` to `self` followed by `as`

### `update` keyword + `<|` operator (new, alongside `set`/`<-`)
- `update` declares a patch handler; `set` declares a put handler — semantics are up to the code
- `<|` token added to lexer; `update` added as keyword
- Parser handles `update` declaration identically to `set`, produces `@<|` wire handler
- `<|` send parsing at all SET sites, with `updateOp: '<|'` field on AST nodes
- All three codegens dispatch `@<|` vs `@<-` based on `updateOp` field
- Named-only arg sends (`a <| name: "val"`) required new parser path — leading named args before any positional
- Fixed named-only payload bug in all three codegens (was generating `[, {map}]` instead of `{map}`)

## Actor marshaling / spin-down analysis

### The question
Can a stateful actor be marshaled (serialized) and later unmarshaled (reconstructed as a live process)? Two sticky points: closures and function-valued variables.

### What's in an actor's state
1. `ref` declarations — explicit named state
2. Constructor params — also explicit named state
3. Child actor instances — recursive actor state
4. Closures assigned to variables — function label + captured values

### Key insight: Rust already solved this

The self-send epic turned function variables into **string labels** dispatched through `handle_op`. The Rust codegen stores closure captures explicitly in `self.state`:

```rust
// Definition site:
self.state.insert("_cap__lambda_0_n".to_string(), json!(n));
let factory = Value::String("_lambda_0".to_string());

// Dispatch:
"_lambda_0" => {
    let n = self.state.get("_cap__lambda_0_n").cloned()...;
    // body uses captured n
}
```

This means:
- **Function identity** = a string label (`"_lambda_0"`)
- **Captured values** = entries in `self.state` under deterministic keys (`"_cap__lambda_0_n"`)
- **Function body** = compiled code (a match arm), not data

To marshal a Rust actor: serialize `self.state`. It already contains refs, child actor state, and closure captures. To unmarshal: deserialize into `self.state` — the dispatch match arms work as-is.

### JS is the outlier

JS uses real closures via IIFE capture (`wrapWithCapture`). The Rust strategy is already partially applied in JS:
- `FnRef` (`&name`) → string label, dispatched via `#selfSend`
- Lambda-as-argument (trailing blocks) → `_lambda_N` handlers

What remains: extend this to ALL lambda assignments so JS matches the Rust pattern of dispatch-handler-with-state-captures.

### The constraint

Closures are reconstructible if their free variables are all marshable. In Brevity, every value is either:
- Primitive (Integer, Text, Boolean, Float) — trivially serializable
- Structure — JSON-compatible object
- Actor ref — serializable as an address
- Scalar ref — serializable as current value
- Function variable — serializable as label + captured values

No opaque host objects exist. The constraint: **don't introduce them.** Already the design intent.

### Connection to `init`

The old `init` block was explicit unmarshal logic — user-written state reconstruction. The compiler can now generate marshal/unmarshal automatically because:
1. It knows the full state shape (refs, params, child actors)
2. Closure captures are explicit and deterministic (Rust already does this)
3. Function bodies are compiled code, not stored data

## JS lambda lift to dispatch handlers

Completed: all JS lambda assignments now become string labels dispatched through `#selfSend`, with captures stored in private class fields. Matches the Rust pattern.

### What changed in `src/codegen.js`
- Lambda assignments → `"_lambda_N"` string label + `this.#_cap__lambda_N_varName` capture fields
- Lambda calls → `#selfSend` (same as actor function calls)
- Function-typed parameter calls → runtime dispatch (`typeof f === 'string' ? selfSend : directCall`)
- Lambda handler arms added to dispatch chain after public+private handlers
- Handler bodies generated via `genFunctionBodyCode` (not `genLocals`) to support all assignment forms
- Nested lambdas handled via index loop (new handlers registered during iteration)
- Self-reference constant declared for recursive lambdas
- Silent lambdas (return type `.`) set `re = null` so self-send resolves
- Inline lambda captures use comma expressions in `genLambdaArgLabel`

### Outer-ref fallback
Lambdas that read/write outer refs (`RefRead`, `SetStatement` on non-state refs, `RefArg`, child actor sets) remain as closures — they need live ref cell access that can't be captured as a snapshot. Detection via `lambdaUsesOuterRefs()`.

### Codegen parity status
| Pattern | JS | Erlang | Rust |
|---|---|---|---|
| Private fn calls → self-send | ✓ | ✓ | ✓ |
| `&fnRef` → self-send closure | ✓ | ✓ | ✓ |
| Lambda assignment → label + captures | ✓ | ✓ | ✓ (escaping only) |
| Inline lambda args → label | ✓ | ✓ | ✓ |
| Function-typed param calls → dispatch | ✓ | ✓ (runtime `is_binary` check) | ✓ (`call_fn`) |

## Erlang lambda lift to dispatch handlers

Completed: all Erlang lambda assignments now become binary strings (`<<"_lambda_N">>`) dispatched through `self_send`, with captures stored in the process dictionary. Matches the Rust/JS pattern.

### What changed in `src/codegen-erl.js`
- Lambda assignments → `<<"_lambda_N">>` binary + `put('_cap_..._var', Value)` capture storage
- Lambda calls → `self_send(Label, Payload)` (same as actor function calls)
- Function-typed parameter calls → runtime dispatch: `case is_binary(F) of true -> structure_one(self_send(F, ...)); false -> F(...) end`
- Lambda handler `handle_op` clauses added to dispatch chain after public+private handlers
- Nested lambdas handled via index loop (new handlers registered during iteration)
- Self-reference constant declared for recursive lambdas
- Inline lambda captures use `begin put(...), <<"label">> end`
- `genExprScalar` helper wraps `self_send` results with `structure_one` for scalar contexts (BinaryExpr, function args)
- Capture keys use quoted atoms (`'_cap_...'`) for Erlang process dictionary

### Outer-ref fallback
Same as JS — lambdas that read/write outer refs remain as real Erlang funs via `genFunctionLiteral`.
