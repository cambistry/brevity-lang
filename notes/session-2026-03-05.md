## TARGET.md Analysis

Full source to make work:

```
actor FileRep

on apply_all_changes(:path : Text)

  :edits = Edits.fetch(:path)

  :blob_id, :dag_id = Heads.fetch(:path)

  -- get current contents --
  prev_blob = Blobs.fetch(:blob_id)[:blob]
  :contents = Crypto.unpack(blob: prev_blob)

  -- apply edits --
  contents =
    fold(contents) edits (edit, acc)
      apply_change(contents: acc, :edit)[:contents]

  -- store new contents --
  new_blob = Crypto.pack(:contents)[:blob]
  new_blob_id = Blobs.store(blob: new_blob)[:blob_id]
  :status = Heads.new(:path, blob_id: new_blob_id, prev: :dag_id)

  reply :status

proc apply_change(:contents : Text, :edit : EditStruct)
  // ... text manipulation ...
  reply :contents
```

### New features required (not yet implemented)

#### 1. `//` line comments
- Already in memory as spec'd
- Lexer: skip from `//` to end of line
- Easy

#### 2. `-- label --` labeled separators
- `-- get current contents --` — both the stitch separator AND a label
- The text between `--` and `--` is a comment/label, no semantics
- Lexer: tokenize as a no-op (skip)
- Note: prior memory says `--` alone is a stitch separator. Text form is same but with label text

#### 3. `proc` keyword/declaration
- `proc name(params)` — local procedure, NOT an actor
- No message-passing envelope (no `id`, `from`, `re`)
- Called like a function: `apply_change(contents: acc, :edit)`
- Returns a plain value (not a message reply)
- Emits as a JS function, not a class
- But wait — it also uses `reply`... need to clarify if proc uses same reply semantics

#### 4. Actor messaging as expression
- `Edits.fetch(:path)` — dot-notation: `ActorName.op(args)`
- This is an ASYNC operation (message send → await reply)
- The call itself is `await this.#binding.send({ op: { fetch: { path } }, to: 'Edits' })`
- Need to understand binding model: does `binding` have a `send` method that returns a Promise?
- Handler bodies become async if they contain actor calls

#### 5. Sigil LHS assignment
- `:edits = Edits.fetch(:path)` — sigil on LHS
- Means: take the entire reply payload and bind it to local `edits`
- vs. plain assignment `prev_blob = ...` where LHS is a plain identifier
- In current codegen, assignment only has plain IDENT on LHS

#### 6. Multi-destructure LHS
- `:blob_id, :dag_id = Heads.fetch(:path)`
- Comma-separated sigils on LHS → destructure multiple named fields from reply
- Emits as: `const { blob_id, dag_id } = await this.#binding.send(...)`

#### 7. Subscript access on call results
- `Blobs.fetch(:blob_id)[:blob]` — `[:blob]` indexes into the reply
- `apply_change(contents: acc, :edit)[:contents]` — same on proc call
- Emits as: `(await expr).blob` or `(result).contents`

#### 8. `fold` built-in with lambda
- `fold(contents) edits (edit, acc)` then indented body
- Semantics: `edits.reduce((acc, edit) => ..., contents)`
- Lambda arg syntax: `(var, var)` followed by indented body
- Complex: needs lambda codegen

#### 9. Multi-line assignment body (continuation)
- `contents =` followed by newline then `fold(...)` block
- The value can span multiple lines; indentation/block indicates it's the RHS

## Complexity / Build Order

Phase 1 — easy lexer additions:
1. `//` comments (skip to EOL)
2. `--` labeled stitch `-- text --` (skip entire thing)

Phase 2 — `proc` declarations:
3. `proc` keyword → KEYWORD token
4. Parse `proc name(params) body` → ProcDecl AST node
5. Codegen: emit as `function name(params) { ... return value; }`
6. Need to think: does proc use `reply` to return, and does codegen replace `reply` with `return`?

Phase 3 — expressions (no async yet):
7. Subscript access `expr[:key]` and `expr[index]`
8. Function call expression `name(args)` (for proc calls in body)

Phase 4 — actor messaging (async):
9. Actor call expression `Actor.op(args)` → `await binding.send(...)`
10. Sigil LHS: `:name = actorCall` → `const { entire reply } = await ...`
11. Multi-destructure LHS: `:a, :b = actorCall`
12. Handler bodies go async when they contain actor calls

Phase 5 — fold/lambda:
13. `fold(init) collection (vars) body` → `collection.reduce((acc, var) => ..., init)`
14. Lambda body parsing + codegen
