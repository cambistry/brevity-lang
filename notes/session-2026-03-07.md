# Session 2026-03-07 — List type corrections

## What was done

Completed the List type implementation with corrections from user feedback.

### Changes

**`src/parser.js`**
- Bare `List` (no `of`) now returns `'List of Any'` instead of throwing
- `Lists` (plural) alone still throws (only valid in `of` position like `List of Lists of Integers`)

**`src/codegen.js`**
- `LIST_PREAMBLE`: added `_List.toArray(list)` (returns `null` for empty list, otherwise JS array); made `_List.from(arr)` null-safe
- `genListDestructureAssign(stmt, ldIdx)`: added `ldIdx` parameter to namespace temp vars (`_ld0_0`, `_ld1_0` etc.) — supports multiple list destructures per handler; added runtime arity check (throws `'List destructure arity mismatch'` when no `...rest` and tail is not null)
- `genDestructure(params)`: List-typed named params now get `_List.from(_s.named[key])` instead of bulk `{ ... }` destructuring — converts incoming wire arrays to linked lists
- `genReplyField(field, typeEnv)`: accepts typeEnv, applies `_List.toArray()` to List-typed values in reply; sigil shorthand changed to explicit `name: val` form
- `genReBody(fields, typeEnv)`: passes typeEnv to `genReplyField` and `posVal`
- `genHandler`: builds `typeEnv` once and passes to both `genReBody` and `genBvaBody`
- `genFunctionBodyCode`: builds `typeEnv`, passes to `genReBody` for Return; adds `_ldIdx` counter
- `genLocals`: adds `_ldIdx` counter for multiple list destructures

**`__tests__/list.test.js`** — Rewrote with:
- Wire format: incoming lists are flat JS arrays `[3, 4]` (not linked list objects)
- Reply lists are flat JS arrays via `_List.toArray()`; empty list is `null`
- Arity: patterns without `...rest` must exactly match list length; added `_` discards where needed
- Tail (`...t`) has no explicit type, so sent as raw linked list (null or cons cell) — `reply tail: t` is null for single-element list
- New: bare `List` tests (now valid, = `List of Any`)
- New: `List of Any` tests
- New: runtime arity error test
- Removed: compile error tests for bare `List` and `:x : List` (now valid)

## Key invariants

- Empty list: `null` on wire and in memory
- `_List.from(null)` = `null` (safe)
- `_List.toArray(null)` = `null` (empty list stays null on wire)
- Arity check only when no `...rest` in pattern
- `t` in `[h, ...t]` has no inferred type → not auto-converted on reply
- Typed reply fields (e.g. `nums : List of Integers`) get `_List.toArray()` applied
