## What landed

Sections:
1. **In-file** — single actor subscribes to its own `@pub`, `#priv`, and `#parameterized` fns. Behavior-only (no wire assertions).
2. **In-script** — parent subscribes to a local child type's `@pub`, `@pub_w_params`. Behavior-only.
3. **Remote (stubbed publisher)** — DI alias, wire assertion on outbound `subscribe@pub`, stubbed `re` replies drive local state.
4. **Interop** — two separately compiled actors, manually shepherded. Mirrors the cell interop at `keywords/subscribe.test.js:224-277`.

## Design inputs (from discussion)

- Subscribe is uniform: public fns, private fns, and parameterized fns all auto-provision `@subscribe` (alongside built-in reactive refs). User types opt-in by declaring `@subscribe` themselves.
- Params on a subscribe are stored per-subscription on the publisher side. Each `(subscriber, args)` tuple is its own long-lived correlation; body re-evaluates against its own args when any captured `*` ref changes.
- Wire shape: `subscribe@<field>` for no-arg, `[{ args }, 'subscribe@<field>']` for parameterized, `bv-a` carries param types. No inline `<Type>` on the selector unless the publisher projects as multiple types and the caller must disambiguate — otherwise the service interface resolves shape on both ends.
- Call-site syntax stays method-form (`target.fn.subscribe(args) |v| { }`), not a wrapping verb. Consistent with `notes/subscription-via-multi-re-2026-04-18.md` — subscribe isn't a special op.
- No private/protected `subscribe` visibility modifier. Internal self-observation already works via local closure wiring (04-13) or bare public subscribe. Protected tier is a broader visibility-system question.

## Parser/codegen gaps the new tests exercise

### A — `.subscribe(args) |v| { }` (args between selector and handler)  ✅ DONE (JS)

Fixed. Parser now accepts an optional `(args)` after `.subscribe` and before the handler block; `AST.subscribeCall` grew an `args` field; JS codegen emits the args on the wire as `[argsPayload, 'subscribe@field']` with paralleling `bv-a`, matching the DotCallExpr remote pattern.

Section 3 (remote with stubbed publisher) is now fully green on JS — wire shape is correct, arg round-trip through stubbed re works.

### B — `@name.subscribe` (self-subscribe via `@` target)  ❌ pending

Parser rejects `AT` as an expression start in subscribe position. Touches self-routing semantics: a self-subscribe should wire locally to the actor's own closure rather than mailbox-send.

### C — `#name.subscribe` (private target)  ❌ pending

Parser OK, codegen emits `Unknown expression type: SubscribeCall` — missing branch for `#`-prefixed targets in the dispatch.

### D — Publisher-side `@subscribe` auto-provisioning for public fns  ❌ pending (newly discovered)

Section 2 and Section 4 fail even though the call site parses and emits the right wire messages. Root cause: the publisher actor has no handler for `subscribe@pub` when `@pub = { body * 2 }` is a function. The compiler auto-provisions `subscribe@<name>` for cells (`@val *Integer`) but not for public functions.

Needed: for every `@fn = { ... }`, synthesize a `@subscribe@fn` handler that
- registers `(id, from)` in a per-fn subscription list
- replies with initial `re: [currentValue]`
- re-evaluates and pushes when any captured `*` ref changes
- for parameterized fns, stores the caller's args per-subscription and uses them in re-evaluation

This is the biggest remaining gap and touches codegen, not just parsing. Probably the next thing to tackle.
