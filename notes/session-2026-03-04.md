# Brevity Transpiler — Session 2026-03-04

## Goal
Build a transpiler for the Brevity language → TypeScript.

## Prior Art (from memory)
- Brevity is a constrained app-definition language for CAM actors
- Two syntax modes: lineal (double-newline delimited) and delimited (parens + braces)
- `--` stitch: visual separator, no semantics
- `returns` keyword: type annotation in header OR block terminator at tail
- `//` line comments, `---` block comments
- Colon for type annotation, `?` for optional
- `of` keyword for parameterized types (no generics v1): `List of String`
- Compile target: TypeScript

## Session Notes

### Syntax Confirmed
- Spacious handler: `on <op>` + double newline + body
- Dense handler: `on <op>()` — parens make double newline unnecessary (test TODO)
- Indentation is NOT significant — purely conventional
- `reply` is the body terminator — no explicit `end` needed, must be last statement
- `reply <key>: <value>` maps to `re: { <op>: { <key>: <value> } }`

### Compiler Architecture
- `src/lexer.js` — source → tokens
- `src/parser.js` — tokens → AST
- `src/codegen.js` — AST → JS string
- `index.js` — orchestrates pipeline
- compile target: ESM (`export default class`)
- Empty source → empty output `''` (no handlers)
- Tests run with `NODE_OPTIONS=--experimental-vm-modules npx jest --runInBand` (parallel mode has module cache collisions)

### Output shape (actor class)
```js
export default class {
  #binding
  constructor(binding) { this.#binding = binding }
  receive(message) {
    const { id, op, from } = message
    switch (op) {
      case "hello":
        this.#binding.post({ id, re: { hello: { answer: "world" } }, to: from })
        break
    }
  }
}
```

### Features Implemented (2026-03-04 → 2026-03-06)
- Handler params: positional, named (sigil), key-mapped, typed
- Type-based handler dispatch / overloading (`_matchTypes`)
- Silent handlers (`end` keyword — no reply posted)
- Procs (`proc` keyword — reentrant mini-actors called with `await`)
- Parallel assign (`a, b = 1 : Integer, 2 : Integer` — StructureConstructor source)
- Lambdas (`fn = (a) { a + 1 }` or `fn = (a) a + 1`)
  - Lambda call emits `LambdaCallExpr` (`await fn(...)`) vs `ProcCallExpr` (`await this.#nameProc(...)`)
  - `lambdaNames` Set in `parse()` scope tracks assigned lambda names
- `return` statement (mid-body early exit in lambda curlies)
- Implicit return (final expr in curly body → positional arity-1 Structure)
- `return`/`reply` without parens (same-line explicit style):
  - `return a` — bare positional variable
  - `return a, b` — multiple bare positionals
  - `return :a` — sigil
  - `return a: x` — key-value
  - `return a : Integer` — typed positional
  - Same forms for `reply`
  - Gate: `if (hasParen || !sameLine) skipNewlines()` in `parseReplyFields(sameLine)`

### Features Added 2026-03-06 (continued)

#### Open-style params/reply (12 new invalid-case tests)
- `DIVIDER` token: bare `--` or `//` (nothing after) → stitch/block-separator
- Three `parseParams()` modes: paren `(...)`, same-line (stops at NEWLINE/BLOCK_SEP/DIVIDER), open-style (after NEWLINE, terminated by BLOCK_SEP or DIVIDER)
- Open-style `reply` terminated by BLOCK_SEP, DIVIDER, or EOF

#### Auto-unwrap: quashing `a, = fn()` trailing-comma destructure
- Plain `Assign` with call-like RHS (`FunctionCallExpr`, `ProcCallExpr`, `StructureConstructor`) → auto-unwrap `positional[0]`
- `TypedAssign` (`name : Type = expr`): Structure type → keep whole; others → unwrap
- `CALL_LIKE` set (now only `FunctionCallExpr`, `ProcCallExpr`)

#### StructureLiteral: RHS comma-list creates a Structure
- `s = a, b` → `StructureLiteral { positional: [a, b] }` — kept whole in Assign
- `s = :a, :b` → named structure `{ a: a_val, b: b_val }`
- `s = x: expr, y: expr` → named key-value structure
- `s = a, b, :c, :d` → mixed structure `[a, b, { c, d }]`
- `s = a : Integer, b : Integer` → typed positional structure
- `parseRHSValue()` helper: called from body Assign branch; handles SIGIL start, key-value detection, type annotation + COMMA detection
- `parseRHSStructureLiteral(firstElem)` and `parseRHSStructureElem()` helpers

#### s : Structure = val : Type coercion
- `s : Structure = 1 : Integer` → 1-element StructureLiteral (wraps single typed value)
- Handled in `parseTypedAssign()` when typeName === 'Structure' and `: Type` follows value

#### Compile-time arity check
- `a = Structure(x, y)` → error: "Cannot assign 2-arity Structure to 'a' — use ': Structure' type annotation"
- `a = Structure(x)` → OK: auto-unwrap positional[0]

#### Compile-time named-field check
- `(:a, :b) = Structure(a: 1 : Integer)` → error: "Field 'b' not found in Structure literal"
- Under-destructuring OK: `(:a) = Structure(a: 1, b: 2)` passes
- `checkNamedFields(pattern, source)` in codegen.js — called from genLocals() and genFunctionBodyCode()
- Only applies to literal `StructureConstructor` source, not proc/fn calls

#### Features Added 2026-03-07

##### DISCARD token `_`
- `_` in positional destructure generates no binding: `a, _, b = args`
- `parseDestructureAssign()` emits `{ discard: true, idx }` items
- `genDestructureAssign()` skips them: `if (item.discard) return ''`
- Multiple underscores OK: `_, _ = args`

##### Structure.one() — proc/fn call arity check
- `a : Type = fn(...)` → `Structure.one(fn(...), "a")` (runtime error if not exactly 1 positional)
- `a : Type = proc(...)` → same
- Plain `Assign` with CALL_LIKE throws compile error: "requires a type annotation"

##### bv-a enforcement
- All non-empty op payloads require `'bv-a'` in the message → `schema_required`
- `_hasPayload` check at dispatch time; absent bv-a → `{ ex: { [op]: 'schema_required' } }`
- Type matching (`_matchTypes`) now uses bv-a exclusively (not data)

##### Typed local variable enforcement
- Handler/proc bodies: plain `Assign` with non-{StructureLiteral, Function, IndexExpr} value → compile error "requires a type annotation"
- `c : Integer = a + b` → `const c = a + b;` (primitive RHS, use directly)
- `a : Integer = Structure(42 : Integer)` → `const a = (Structure(...)).positional[0];` (StructureConstructor RHS, unwrap)
- `result : Integer = fn(5)` → `Structure.one(fn(5), "result")` (CALL_LIKE RHS)
- `s : Structure = fn(5)` → keep whole structure
- Function lambda bodies (genFunctionBodyCode) remain permissive (lambdas are generic)

##### Typed destructure LHS syntax
- `a : Integer, b : Integer = sub()` — positional items with type
- `result: x : Integer = square(10)` — key-mapped with type
- `a : Integer, result: x : Integer = sub()` — mixed
- `isDestructureStart()` extended: recognizes `key: local : Type = ...` and `TypedIdent,` patterns

##### Bare type declarations (2026-03-07)
- `x : Integer` — bare decl in handler/proc/function body; no JS output, type-annotation only
- `x = 1 : Integer` — typed RHS on plain assign; normalizes to `TypedAssign { x, Integer, 1 }`; `parseRHSValue()` returns `TypedValue` node, caller promotes to `TypedAssign`
- `x : Integer = 2 : Integer` — redundant annotation; `parseTypedAssign()` consumes optional RHS `: Type` and checks it matches LHS type
